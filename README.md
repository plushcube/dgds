# DGDS

Digital goods distribution system — сервис защищённой дистрибуции цифрового контента: авторы публикуют файлы, покупатели получают их расшифрованными только в памяти, а утечка атрибутируется меткой покупки.

Что это за система, какие у неё требования и чего она не защищает — в `docs/project.md`.

## Требования

| Что | Версия и примечание |
| --- | --- |
| CMake | 3.28 или новее, объявлено в `CMakeLists.txt` |
| Компилятор C++23 | проверено на Apple clang 21 и на компиляторе из образа ubuntu 24.04 |
| OpenSSL 3 | библиотека и заголовки: `libssl-dev` в Linux, `openssl@3` в macOS |
| Сеть при сборке | зависимости скачиваются через FetchContent: cpp-httplib v0.56.0, nlohmann/json v3.12.0, googletest v1.17.0 |

Для проверок нужны ещё три инструмента:

| Что | Примечание |
| --- | --- |
| clang-format | проверено на 23.1.2; разные версии форматтера дают разный результат, поэтому версию стоит держать общей |
| cmake-format | 0.6.13. Отдельной формулы Homebrew нет, ставится из pip вместе с PyYAML: `python3 -m venv ~/.local/venvs/cmake-format && ~/.local/venvs/cmake-format/bin/pip install cmakelang pyyaml` |
| python3 | нужен драйверу замеров `tools/measure_performance.py` |

Docker нужен только для сборки образа и отрисовки диаграмм; для сборки, тестов и проверок он не требуется.

## Сборка и проверка

```sh
cmake -B .build
cmake --build .build --parallel
ctest --test-dir .build --output-on-failure
```

Полная проверка одной командой — формат C++ и CMake, свежесть рендеров диаграмм, целостность слоёв, сборка и тесты:

```sh
./self_check.sh
```
